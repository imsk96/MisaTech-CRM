# Multi-Tenant CRM with External Storage Mode

A production-ready multi-tenant CRM SaaS that uses **Google Sheets and Excel as primary data storage**, with Supabase as the control layer for authentication, company isolation, role management, and approval workflows.

## ✨ Features

### Multi-Tenant Architecture
- Each company is isolated with `company_id`
- Row Level Security (RLS) ensures data isolation
- No cross-company data access

### Role-Based Access Control
- **Admin**: Can approve/reject actions, manage integrations
- **Staff**: Can create/update/delete, but requires approval

### Approval Workflow
1. Staff performs action → stored in `approvals` table
2. Admin reviews pending approvals
3. Approved actions → Sync Engine → External Storage
4. Rejected actions → discarded

### External Storage Integration
- **Google Sheets**: Full OAuth flow, column mapping, real-time sync
- **Excel**: File upload support, parsing, local storage fallback

### Sync Engine
- Rate limiting handling
- Automatic retries with exponential backoff
- Conflict resolution
- Comprehensive logging

## 🚀 Setup Instructions

### Step 1: Install Dependencies

```bash
cd /workspace
npm install
```

### Step 2: Configure Supabase

1. Create a new project at [supabase.com](https://supabase.com)
2. Go to SQL Editor and run `supabase-schema.sql`
3. Get your credentials:
   - Project URL
   - Anon/Public Key

### Step 3: Environment Configuration

Create a `.env` file (or set environment variables):

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

### Step 4: Start Development Server

```bash
npm run dev
```

The app will open at `http://localhost:3000`

### Step 5: Build for Production

```bash
npm run build
```

Deploy the `dist/` folder to Netlify or any static host.

## 🗄 Database Schema

### Core Tables

| Table | Purpose |
|-------|---------|
| `companies` | Tenant isolation |
| `users` | User accounts with roles |
| `approvals` | Pending/approved actions |
| `integrations` | External storage configs |
| `sync_logs` | Audit trail |
| `staff` | Extended staff info |
| `excel_data` | Excel fallback storage |

### Key RLS Policies

```sql
-- Users can only see their company's data
CREATE POLICY company_isolation ON companies
FOR ALL USING (id IN (
    SELECT company_id FROM users WHERE users.id = auth.uid()
));

-- Staff can create approvals
CREATE POLICY approvals_staff_create ON approvals
FOR INSERT WITH CHECK (
    company_id IN (SELECT company_id FROM users WHERE users.id = auth.uid())
    AND created_by = auth.uid()
);

-- Admins can approve/reject
CREATE POLICY approvals_admin_update ON approvals
FOR UPDATE USING (
    company_id IN (
        SELECT company_id FROM users 
        WHERE users.id = auth.uid() AND role = 'admin'
    )
);
```

## 🔌 Google Sheets Integration

### OAuth Flow

1. User clicks "Connect Google Sheets"
2. Redirect to Google OAuth
3. Store `access_token`, `refresh_token`, `sheet_id`
4. Use tokens for API calls

### Column Mapping

Each module maps fields to sheet columns:

```json
{
  "leads": {
    "lead_name": "A",
    "email": "B",
    "phone": "C",
    "company": "D",
    "status": "E"
  }
}
```

### API Endpoints

- **Read**: `GET /spreadsheets/{sheetId}/values/{range}`
- **Create**: `POST /spreadsheets/{sheetId}/values/{range}:append`
- **Update**: `PUT /spreadsheets/{sheetId}/values/{range}`
- **Delete**: Clear row values

## ✅ Approval Workflow

### Staff Action Flow

```javascript
// Staff creates a lead
const result = await approvalEngine.submitForApproval(
  'leads',
  'create',
  { lead_name: 'John Doe', email: 'john@example.com' }
);
// Status: pending
```

### Admin Review Flow

```javascript
// Admin gets pending approvals
const pending = await approvalEngine.getPendingApprovals();

// Admin approves
await approvalEngine.approve(approvalId);
// → Sync Engine executes → Google Sheets updated
```

### Sync Execution

```javascript
// Sync Engine processes approved action
await syncEngine.processApproval(approvalId);
// → Calls Google Sheets API
// → Logs result in sync_logs
```

## 🔒 Security

### Multi-Tenant Isolation

- All queries filtered by `company_id`
- RLS prevents cross-tenant access
- Service role key only used by Sync Engine

### Data Protection

- Passwords hashed with bcrypt
- OAuth tokens encrypted at rest
- XSS prevention via sanitization

### Access Control

| Action | Staff | Admin |
|--------|-------|-------|
| Create record | ✓ (pending) | ✓ (direct) |
| Update record | ✓ (pending) | ✓ (direct) |
| Delete record | ✓ (pending) | ✓ (direct) |
| Approve actions | ✗ | ✓ |
| Manage integrations | ✗ | ✓ |
| View sync logs | ✗ | ✓ |
